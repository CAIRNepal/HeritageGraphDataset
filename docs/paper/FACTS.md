## I. Pipeline

| stage | what it does | input | output |
|---|---|---|---|
| 1. Collection | Playwright reads each DANAM record page (2–4 s apart), one JSON per record; exports three tables | `data_collection/resourceids.csv` | `data_collection/data/raw/*.json`, `data_collection/data/exports/{monuments,events,objects}.csv` |
| 2. Staging | keeps the DANAM fields, adds derived columns (code, Nepali name, class, AAT style, condition), separates empty records | `exports/monuments.csv` | `staging/monuments.csv`, `staging/skipped_rows.csv`, candidate files |
| 3. Graph | RDF from the staged monuments and DANAM's event and object tables | `staging/monuments.csv`, `exports/events.csv`, `exports/objects.csv` | graph in memory; Turtle, N-Triples, JSON-LD |
| 4. Checks | undeclared terms and SHACL against the ontology; tests | built graph, `ontology/`, `vocab/hgn.ttl` | alignment report |
| 5. Release | serialisations, `metadata.json`, checksums | built graph | `releases/<version>/`, `latest/` |

Runtimes on this machine (Darwin arm64): staging 0.9 s (rerun into the scratch directory; reproduces `staging/monuments.csv` exactly: yes), graph build 1.5 s, serialisation of all formats 6.6 s, alignment check 13 s. Collection is not timed here (it contacts DANAM).
